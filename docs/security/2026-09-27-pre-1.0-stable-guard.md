# A pre-1.0 stable-channel guard, 2026-09-27

Scope: W1 from the 09-25 gap audit -- "every plugin workflow's `channel`
dispatch input still defaults to `stable` with no refusal for a 0.x
`pluginVersion`."

## The gap

Every plugin repository's own workflow (e.g. `enginehost-godot-plugin`
`plugin-core`'s `.github/workflows/enginehost-android.yml`) exposes a
`workflow_dispatch` `channel` choice (`stable`/`testing`, defaulting to
`stable`) that anyone who can dispatch it can pick, with nothing stopping
a bundle still at `pluginVersion` `0.x` -- meaning nobody has yet said it
was used with real games on hardware long enough to trust, by the project's
own definition of `stable` (`docs/plugin-catalog.md`, "Publishing") --
from being tagged and released on the channel every person's device
trusts by default (`stable` is Enginehost's own default channel choice in
Settings).

Each plugin repository's `channel` input, its tag-shaping `case` statement
and its `gh release create` calls are copy-pasted per repository (not
`workflow_call`ed), so a check added only to one repository's copy would
have to be re-added, correctly, to every plugin repository that exists now
and every one scaffolded later. The one mechanism actually shared by every
plugin repository is `.github/workflows/sign-engine-bundle.yml`
(`Droidtop/enginehost`), which every repository already calls, pinned by
commit, to do the one thing none of their own code is trusted to do: use
the signing key (`docs/security/2026-09-24-ci-supply-chain.md`). That is
where this guard belongs, for the same reason the signing step itself
lives there and nowhere else: a plugin repository's own workflow could
have this check wrong, or missing, or removed in a later edit, and it
would not matter, because nothing it produces is a real release until this
workflow has signed it.

## What ships

`sign-engine-bundle.yml` gains an optional `channel` input (`stable`,
`testing`, `unstable`, or empty for a run that is not being published at
all -- an ordinary push build). Its `Sign` step, which already unpacks
`bundle-metadata.json` to read the payload it is about to sign, refuses to
sign at all when `channel` is `stable` and that same metadata's
`pluginVersion` has a major version below 1. The refusal happens before
`build-engine-bundle.py` ever runs, so no signed artifact exists for the
`publish` job downstream to release -- the plugin repository's own
publish step has nothing to promote, whatever tag or channel it computed
for itself.

A caller that never passes `channel` (every existing `uses:` block, until
re-pinned) gets today's behaviour exactly: the input defaults to `""`,
which the guard's `[ "$CHANNEL" = stable ]` check never matches, so nothing
is refused. The guard only takes effect once a plugin repository's own
workflow is re-pinned to a tooling commit at or after this one AND passes
its own `channel` dispatch input through:

```yaml
uses: Droidtop/enginehost/.github/workflows/sign-engine-bundle.yml@<new sha>
with:
  tooling-sha: <new sha>
  channel: ${{ inputs.channel }}
  # ...unchanged
```

## Re-pinning

Re-pinned so far (this change): `enginehost-godot-plugin`'s `plugin-core`
branch, merged into all 9 `plugin/*` lines (`4.0`, `4.1`, `4.2`, `4.3`,
`4.4`, `4.5`, `4.5-embedded-pack`, `4.6`, `4.7.1`) -- the same lines task 2
(release-tag pinning) touches in this session, so both land together.
Every Godot line is at `pluginVersion` `0.1` today, so a `channel: stable`
dispatch on any of them is refused by this guard until a line is actually
promoted past 1.0.

**Not yet re-pinned: every other plugin repository** (Ren'Py, KiriKiri,
CMVS, CatSystem2, mkxp-z, EasyRPG, MV/MZ, ONScripter, Buriko, LÖVE2D, AGS,
and any other `enginehost-*-plugin` line not touched in this session).
Until each one bumps its own `tooling-sha` pin and adds `channel: ${{
inputs.channel }}` to its `sign` job, that repository's own `stable`
dispatch is unguarded exactly as before -- the fix exists but does nothing
for a caller that has not adopted the new input. This is real, standing
work across every remaining plugin repository, not a one-line follow-up;
it is out of this session's scope beyond the Godot line and is named here
so it is not mistaken for done.
